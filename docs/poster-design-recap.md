## スキルへ持ち帰る判断

1. 形成では「何を加える／減らすと何が分かるか」を比較する。レビューでは「この候補版で何が観察でき、どの影響があるか」を報告する。
2. 監査基準そのものも目的に照らして見直す。背景箱等の具体手段を、根拠なく受入条件へ固定しない。
3. 情報構造の変化を実成果物で確かめる。局所CSSの修正が中央の大きな空白など別の問題を生むことがある。
4. 引用・分析・解釈・集計の出所を追跡できるようにし、ラベルと配置でも違いを示す。
5. 別媒体への展開では意味の役割を保ち、密度・順序・実装・検査を作り直す。
6. レビューの合格は対象版と確認範囲を伴う判断として記録する。新しいユーザーの評価や目的に応じて形成へ戻れるようにする。

これらはケースに基づく設計上の提案である。今回参照した記録から、複数媒体における改善効果の因果関係や性能差を算出することはできない。
